# Hexagonal Architecture Learning Path

## O que quero entender?

Uma sequência lógica de pré-requisitos para compreender Hexagonal Architecture com profundidade suficiente para aplicá-la conscientemente (e reconhecer quando não usá-la).

## Resumo

1. Software Architecture *(fundamentos gerais — nota ainda não criada nesta base)*
2. [[Coupling]] & [[Cohesion]]
3. Abstraction *(coberto de forma aplicada dentro de [[Ports]] e [[Dependency Inversion]])*
4. [[Dependency Inversion]]
5. [[Dependency Injection]]
6. [[Domain]]
7. [[Application Core]]
8. [[Use Case]]
9. [[Ports]]
10. [[Adapters]]
11. [[Dependency Rule]] (direção das dependências)
12. Testing (unit tests, integration tests, test doubles — ver seção "Testabilidade" em [[Hexagonal Architecture]])
13. Trade-offs (ver seção "Trade-offs" em [[Hexagonal Architecture]])
14. [[Hexagonal vs Clean vs Onion]]
15. Java Implementation — ver seção "Java" em [[Hexagonal Architecture]] e notas de [[Java 21]]
16. Spring Boot Integration — preparação para etapa futura (ver seção "Ponte para Spring Boot" em [[Hexagonal Architecture]])

## Conceitos importantes

A ordem importa: Dependency Inversion precisa ser entendido antes de Ports fazer sentido; Ports e Adapters precisam ser entendidos antes da Dependency Rule ficar clara (especialmente a diferença entre direção lógica e direção de código).

## Exemplo prático

Usar o exemplo "Create Order" documentado em [[Hexagonal Architecture]] como estudo de caso para percorrer toda a sequência acima.
